#MP-Declare Model
## Activities
- **Submit Timesheet**: The 'Submit Timesheet' activity represents the submission of an employee's timesheet for payroll processing.
- **Approve Timesheet**: The 'Approve Timesheet' activity involves reviewing and approving or rejecting the submitted timesheet.
- **Calculate Gross Pay**: The 'Calculate Gross Pay' activity computes the gross pay based on hours worked and pay rate.
- **Calculate Deductions**: The 'Calculate Deductions' activity calculates tax and insurance deductions from the gross pay.
- **Calculate Net Pay**: The 'Calculate Net Pay' activity determines the net pay after subtracting deductions from gross pay.
- **Generate Paystub**: The 'Generate Paystub' activity involves creating a paystub document for the employee.
- **Process Payment**: The 'Process Payment' activity handles the disbursement of payment to the employee.
- **Update Payroll Records**: The 'Update Payroll Records' activity updates the payroll system with the processed payment information.
- **Review Payroll Report**: The 'Review Payroll Report' activity involves reviewing the payroll report for accuracy and completeness.
- **Distribute Paystub**: The 'Distribute Paystub' activity involves distributing the generated paystub to the employee.

## Attributes
- **Hours Worked: integer between 0 and 80**: The attribute 'Hours Worked: integer between 0 and 80' represents the number of hours an employee has worked during the pay period.
- **Pay Rate: float between 10.0 and 100.0**: The attribute 'Pay Rate: float between 10.0 and 100.0' represents the hourly pay rate for the employee.
- **Gross Pay: float between 0.0 and 10000.0**: The attribute 'Gross Pay: float between 0.0 and 10000.0' represents the total earnings before any deductions.
- **Tax Deduction: float between 0.0 and 5000.0**: The attribute 'Tax Deduction: float between 0.0 and 5000.0' represents the amount deducted for taxes.
- **Insurance Deduction: float between 0.0 and 1000.0**: The attribute 'Insurance Deduction: float between 0.0 and 1000.0' represents the amount deducted for insurance premiums.
- **Net Pay: float between 0.0 and 10000.0**: The attribute 'Net Pay: float between 0.0 and 10000.0' represents the final amount paid to the employee after deductions.
- **Timesheet Status: Submitted, Approved, Rejected**: The attribute 'Timesheet Status: Submitted, Approved, Rejected' specifies the current status of the timesheet.
- **Payment Method: Direct Deposit, Check**: The attribute 'Payment Method: Direct Deposit, Check' specifies the method by which the employee receives payment.
- **Employee ID: integer between 1000 and 9999**: The attribute 'Employee ID: integer between 1000 and 9999' represents the unique identification number assigned to each employee.

## Interleaved Description
The MP-Declare process model for the payroll processing is described as follows:

### **Trace-Related Constraints**
#### **Init Constraints**
The process begins with the activity 'Submit Timesheet,' which involves an employee submitting their timesheet for payroll processing, capturing the 'Employee ID', 'Hours Worked', and setting the 'Timesheet Status' to 'Submitted'.

### **Flexible Ordering Constraints**

#### **Response Constraints**
1. If the 'Submit Timesheet' activity occurs, then the 'Approve Timesheet' activity must eventually occur. This ensures that every submitted timesheet is reviewed and either approved or rejected, establishing a sequential flow from submission to approval.
2. If the 'Approve Timesheet' activity occurs, then the 'Calculate Gross Pay' activity must eventually occur. This ensures that after a timesheet is approved, the gross pay is computed based on the 'Hours Worked' and 'Pay Rate', creating a logical progression in the payroll calculation.
3. If the 'Calculate Gross Pay' activity occurs, then the 'Calculate Deductions' activity must eventually occur. This ensures that after the gross pay is determined, the tax and insurance deductions are calculated, maintaining a cause-effect relationship in the financial computation.
4. If the 'Calculate Deductions' activity occurs, then the 'Calculate Net Pay' activity must eventually occur. This ensures that after deductions are computed, the net pay is determined by subtracting deductions from the gross pay, continuing the sequential calculation flow.
5. If the 'Calculate Net Pay' activity occurs, then the 'Process Payment' activity must eventually occur. This ensures that after the net pay is calculated, the payment is disbursed to the employee, linking the calculation phase to the payment phase.
6. If the 'Process Payment' activity occurs, then the 'Update Payroll Records' activity must eventually occur. This ensures that after payment is processed, the payroll system is updated with the payment information, maintaining accurate records.
7. If the 'Update Payroll Records' activity occurs, then the 'Review Payroll Report' activity must eventually occur. This ensures that after records are updated, the payroll report is reviewed for accuracy and completeness, concluding the record-keeping phase.
8. If the 'Process Payment' activity occurs, then the 'Distribute Paystub' activity must eventually occur within 0 to 24 hours. This ensures that the paystub is distributed to the employee within a day of processing the payment, maintaining timely communication.

### **Negative Flexible Ordering Constraints**

#### **Not Response Constraint**
The 'Approve Timesheet' activity with the condition 'Timesheet Status is Rejected' must not be followed by a 'Submit Timesheet' activity at any point later in the same process instance. This ensures that once a timesheet is rejected, no new timesheet submissions are allowed, preventing a cycle of resubmission after rejection and maintaining process integrity.
