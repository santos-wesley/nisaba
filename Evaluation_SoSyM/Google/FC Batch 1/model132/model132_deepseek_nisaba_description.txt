#MP-Declare Model
## Activities
- **Monitor Seismic Activity**: The 'Monitor Seismic Activity' activity involves continuously observing and recording seismic data to detect potential earthquakes or ground movements.
- **Assess Disaster Risk**: The 'Assess Disaster Risk' activity evaluates the potential impact and likelihood of a disaster based on seismic data and other factors.
- **Issue Early Warning**: The 'Issue Early Warning' activity involves disseminating alerts and warnings to authorities and the public about an impending disaster.
- **Activate Emergency Response**: The 'Activate Emergency Response' activity initiates the formal emergency response protocols and mobilizes resources.
- **Deploy Rescue Teams**: The 'Deploy Rescue Teams' activity involves sending trained personnel to affected areas to conduct search and rescue operations.
- **Provide Medical Assistance**: The 'Provide Medical Assistance' activity delivers medical care and treatment to injured individuals in the disaster zone.
- **Distribute Relief Supplies**: The 'Distribute Relief Supplies' activity involves allocating and delivering essential items such as food, water, and blankets to affected populations.
- **Evacuate Affected Population**: The 'Evacuate Affected Population' activity involves moving people from dangerous areas to safer locations.
- **Establish Temporary Shelters**: The 'Establish Temporary Shelters' activity sets up temporary housing and accommodation for displaced individuals.
- **Conduct Damage Assessment**: The 'Conduct Damage Assessment' activity evaluates the extent of structural and environmental damage caused by the disaster.

## Attributes
- **Seismic Magnitude: integer between 0 and 10**: The attribute 'Seismic Magnitude: integer between 0 and 10' represents the measured strength of an earthquake on the Richter scale.
- **Risk Score: float between 0.0 and 100.0**: The attribute 'Risk Score: float between 0.0 and 100.0' represents the calculated risk level of a potential disaster scenario.
- **Warning Level: Low, Medium, High, Critical**: The attribute 'Warning Level: Low, Medium, High, Critical' specifies the severity level of the early warning issued to the public.
- **Response Status: Initiated, Ongoing, Completed**: The attribute 'Response Status: Initiated, Ongoing, Completed' indicates the current phase of the emergency response activation.
- **Teams Deployed: integer between 0 and 50**: The attribute 'Teams Deployed: integer between 0 and 50' represents the number of rescue teams sent to the affected area.
- **Injured Count: integer between 0 and 10000**: The attribute 'Injured Count: integer between 0 and 10000' represents the number of individuals requiring medical attention.
- **Supplies Distributed: integer between 0 and 20000**: The attribute 'Supplies Distributed: integer between 0 and 20000' represents the quantity of relief items delivered to affected populations.
- **People Evacuated: integer between 0 and 50000**: The attribute 'People Evacuated: integer between 0 and 50000' represents the number of individuals relocated from danger zones.
- **Shelters Established: integer between 0 and 20**: The attribute 'Shelters Established: integer between 0 and 20' represents the number of temporary shelters set up for displaced persons.
- **Damage Estimate: float between 0.0 and 1000000000.0**: The attribute 'Damage Estimate: float between 0.0 and 1000000000.0' represents the estimated financial cost of the damage caused by the disaster.

## Interleaved Description
The MP-Declare process model for the disaster response process is described as follows:

### **Trace-Related Constraints**
#### **Init Constraints**
The process begins with the activity 'Monitor Seismic Activity,' which involves continuously observing and recording seismic data to detect potential earthquakes or ground movements, using the 'Seismic Magnitude' attribute.

### **Dependency Constraints**
#### **Responded Existence Constraints**
If a 'Monitor Seismic Activity' activity occurs, then an 'Issue Early Warning' activity must eventually occur after it at some point in the same process instance. This establishes a dependency where the monitoring of seismic activity necessitates the issuance of an early warning, enhancing coherence in the process.

### **Immediate Ordering Constraints**
#### **Chain Response Constraints**
Whenever an 'Issue Early Warning' activity occurs, it must be immediately followed by an 'Activate Emergency Response' activity in the next event position, with no other events in between. This captures a direct cause-and-effect relationship, ensuring that the warning is immediately acted upon by initiating emergency protocols.

### **Flexible Ordering Constraints**
#### **Response Constraints**
1. If an 'Activate Emergency Response' activity occurs, then a 'Deploy Rescue Teams' activity must eventually occur after it at some point in the same process instance. This defines an ordered flow where the activation of emergency response leads to the deployment of rescue teams.
2. If a 'Deploy Rescue Teams' activity occurs, then a 'Provide Medical Assistance' activity must eventually occur after it at some point in the same process instance. This ensures that the deployment of teams is followed by medical care for the injured.
3. If a 'Provide Medical Assistance' activity occurs, then a 'Distribute Relief Supplies' activity must eventually occur after it at some point in the same process instance. This ensures that medical assistance is followed by the distribution of essential supplies.
4. If an 'Assess Disaster Risk' activity occurs with a Risk Score greater than 70, then an 'Evacuate Affected Population' activity must eventually occur after it at some point in the same process instance. This ensures that high-risk assessments trigger evacuations.
5. If an 'Assess Disaster Risk' activity occurs with a Risk Score greater than 70, then an 'Establish Temporary Shelters' activity must eventually occur after it at some point in the same process instance. This ensures that high-risk assessments also lead to the setup of shelters.
6. If a 'Provide Medical Assistance' activity occurs, then a 'Distribute Relief Supplies' activity must eventually occur after it within 0 to 24 hours in the same process instance. This ensures that relief supplies follow medical assistance within a specific time window.

#### **Succession Constraints**
A 'Conduct Damage Assessment' activity must be followed by a 'Distribute Relief Supplies' activity at some point later in the same process instance. Conversely, a 'Distribute Relief Supplies' event can occur only if a 'Conduct Damage Assessment' event has occurred before it within the same process instance. This establishes a causal link, ensuring that damage assessment logically precedes and justifies the distribution of relief supplies, creating a cohesive progression within the model.
