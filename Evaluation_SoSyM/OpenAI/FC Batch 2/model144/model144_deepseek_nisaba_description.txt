#MP-Declare Model
## Activities
- **Assess Initial Condition**: The 'Assess Initial Condition' activity involves evaluating the client's initial state and needs at the beginning of the therapeutic process.
- **Develop Treatment Plan**: The 'Develop Treatment Plan' activity involves creating a customized therapeutic plan based on the client's initial assessment.
- **Schedule First Session**: The 'Schedule First Session' activity involves arranging the initial therapy session with the client.
- **Conduct Therapy Session**: The 'Conduct Therapy Session' activity involves delivering therapeutic interventions to the client during a session.
- **Evaluate Progress**: The 'Evaluate Progress' activity involves assessing the client's improvement and development throughout the treatment.
- **Adjust Treatment Plan**: The 'Adjust Treatment Plan' activity involves modifying the therapeutic approach based on the client's progress evaluation.
- **Provide Feedback**: The 'Provide Feedback' activity involves sharing observations and recommendations with the client regarding their treatment.
- **Schedule Follow-Up**: The 'Schedule Follow-Up' activity involves arranging subsequent therapy sessions to continue the treatment.
- **Complete Treatment**: The 'Complete Treatment' activity involves finalizing the therapeutic process with the client.
- **Conduct Final Assessment**: The 'Conduct Final Assessment' activity involves performing a comprehensive evaluation of the client's progress at the end of treatment.

## Attributes
- **Client ID: integer between 1 and 999999**: The attribute 'Client ID: integer between 1 and 999999' represents the unique identification number assigned to each client for tracking purposes.
- **Session Type: Initial, Follow-Up, Crisis**: The attribute 'Session Type: Initial, Follow-Up, Crisis' specifies the category of therapy session being conducted.
- **Progress Score: float between 0.0 and 100.0**: The attribute 'Progress Score: float between 0.0 and 100.0' represents the numerical measurement of the client's therapeutic progress.
- **Therapist ID: integer between 1 and 9999**: The attribute 'Therapist ID: integer between 1 and 9999' represents the unique identification number assigned to each therapist.
- **Feedback Type: Positive, Neutral, Negative**: The attribute 'Feedback Type: Positive, Neutral, Negative' specifies the nature of the feedback provided to the client.
- **Treatment Status: Ongoing, Adjusted, Completed**: The attribute 'Treatment Status: Ongoing, Adjusted, Completed' indicates the current state of the client's treatment plan.

## Interleaved Description
The MP-Declare process model for the therapeutic process is described as follows:

### **Trace-Related Constraints**
#### **Init Constraints**
The process begins with the activity 'Assess Initial Condition,' which involves evaluating the client's initial state and needs at the beginning of the therapeutic process. This activity must be the first to occur, establishing the foundational context for the entire treatment journey.
#### **End Constraints**
The process concludes with the activity 'Conduct Final Assessment,' which involves performing a comprehensive evaluation of the client's progress at the end of treatment. This activity must be the last to occur, ensuring a formal and thorough closure to the therapeutic process.

### **Frequency Constraints**

#### **Existence Constraints**
The 'Conduct Therapy Session' activity must occur at least three times in the process. This ensures that multiple therapeutic interventions are delivered, providing sufficient depth and continuity for the client's treatment.

#### **Absence Constraints**
The 'Provide Feedback' activity must not occur five times in the process. This contrast specifies what is not permissible, reinforcing process integrity by preventing excessive feedback that could disrupt the therapeutic flow.

### **Flexible Ordering Constraints**

#### **Precedence Constraints**
1. The activity 'Develop Treatment Plan' establishes the initial context that the 'Assess Initial Condition' activity must have occurred before it. This ensures that a treatment plan is created based on the client's initial assessment.
2. The activity 'Conduct Therapy Session' is permitted to occur only if an 'Evaluate Progress' activity has occurred before it within the same process instance. This ensures that therapy sessions are informed by prior progress evaluations, guiding the logical sequence of therapeutic interventions.
3. The activity 'Schedule First Session' is permitted to occur only if a 'Conduct Therapy Session' activity has occurred before it within the same process instance, and this must occur within 0 to 30 minutes. This establishes a time-bound context where the scheduling of the first session depends on a preceding therapy session, ensuring immediate follow-up.

#### **Response Constraints**
1. If a 'Schedule First Session' activity occurs, then a 'Conduct Therapy Session' activity must eventually occur after it. This defines an ordered flow, ensuring that scheduling the first session leads to a therapy session at some point in the process.
2. If an 'Evaluate Progress' activity occurs, then an 'Adjust Treatment Plan' activity must eventually occur after it. This establishes a sequence where progress evaluation prompts a subsequent adjustment to the treatment plan, ensuring a cohesive temporal structure.

#### **Not Succession Constraints**
The 'Adjust Treatment Plan' activity and the 'Complete Treatment' activity must not occur such that 'Adjust Treatment Plan' is followed by 'Complete Treatment' at any point in the same process instance. This contrast restricts overlapping sequences, preserving the model's intended flow by ensuring that treatment adjustments do not lead directly to completion.

### **Immediate Ordering Constraints**

#### **Chain Response Constraints**
1. Whenever a 'Develop Treatment Plan' activity occurs, it must be immediately followed by a 'Schedule First Session' activity in the next event position, with no other events in between. This cause-effect relationship ensures a direct and immediate progression from planning to scheduling.
2. Whenever an 'Adjust Treatment Plan' activity occurs, it must be immediately followed by a 'Provide Feedback' activity in the next event position. This captures immediate succession, ensuring that adjustments are directly communicated through feedback.
3. Whenever a 'Provide Feedback' activity occurs, it must be immediately followed by a 'Schedule Follow-Up' activity in the next event position, within 0 to 48 hours. This tight cause-effect link ensures that feedback is promptly followed by scheduling the next session, within a specific time window.

### **Exclusivity Constraints**

#### **Not Co-Existence Constraints**
The 'Schedule First Session' activity and the 'Schedule Follow-Up' activity cannot both occur within the same process instance. This contrast sets an exclusion rule, ensuring that initial scheduling and follow-up scheduling are mutually exclusive, thereby maintaining process integrity by preventing conflicting scheduling events.
