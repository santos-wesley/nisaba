## Activities
- **Submit Request**: The 'Submit Request' activity represents the initial submission of a request by an employee.
- **Review Request**: The 'Review Request' activity involves a manager reviewing the submitted request.
- **Approve Request**: The 'Approve Request' activity is when a manager approves the request.
- **Reject Request**: The 'Reject Request' activity occurs when a manager rejects the request.
- **Setup Remote Access**: The 'Setup Remote Access' activity sets up remote access for the employee after approval.
- **Update Payroll**: The 'Update Payroll' activity updates the payroll system based on the request.
- **Notify Employee**: The 'Notify Employee' activity notifies the employee about the request outcome.
- **Monitor Performance**: The 'Monitor Performance' activity monitors the employee's performance post-request.
- **Revoke Access**: The 'Revoke Access' activity revokes remote access if necessary.
- **Complete Survey**: The 'Complete Survey' activity involves the employee completing a performance survey.

- **Payroll Status: Updated, Pending**: The attribute 'Payroll Status: Updated, Pending' tracks the status of payroll updates related to the request.
- **Manager ID: integer between 1 and 9999**: The attribute 'Manager ID: integer between 1 and 9999' is a unique identifier for the manager handling the request.
- **Access Status: Setup, Revoked**: The attribute 'Access Status: Setup, Revoked' indicates the current status of remote access for the employee.
- **Performance Rating: Excellent, Good, Average, Poor**: The attribute 'Performance Rating: Excellent, Good, Average, Poor' reflects the performance level of the employee as monitored.
- **Notification Status: Sent, Pending**: The attribute 'Notification Status: Sent, Pending' tracks whether the employee has been notified about the request.
- **Survey Score: float between 0.0 and 10.0**: The attribute 'Survey Score: float between 0.0 and 10.0' represents the score obtained from the employee's performance survey.

There is no requirement on how soon or what events may occur in between. Multiple 'Submit Request' can be pending at the same time, and a single 'Review Request' can fulfill the obligation for all preceding 'Submit Request'. This means that the process is compliant if 'Approve Request' event occurs, 'Reject Request' event occurs, or both occur. There is no restriction on the order or the number of times they occur.
