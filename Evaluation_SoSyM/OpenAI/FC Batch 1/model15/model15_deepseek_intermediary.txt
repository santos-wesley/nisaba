## Activities
- **Submit Request**: The 'Submit Request' activity represents the initiation of a request by an employee.
- **Review Request**: The 'Review Request' activity involves evaluating the submitted request for completeness and validity.
- **Approve Request**: The 'Approve Request' activity represents the formal approval of a request by a manager.
- **Reject Request**: The 'Reject Request' activity represents the formal rejection of a request by a manager.
- **Setup Remote Access**: The 'Setup Remote Access' activity involves configuring remote access permissions for the employee.
- **Update Payroll**: The 'Update Payroll' activity involves adjusting the employee's payroll information based on the request.
- **Notify Employee**: The 'Notify Employee' activity involves sending a notification to the employee regarding the request status.
- **Monitor Performance**: The 'Monitor Performance' activity involves tracking and evaluating the employee's performance.
- **Revoke Access**: The 'Revoke Access' activity involves removing the employee's remote access permissions.
- **Complete Survey**: The 'Complete Survey' activity involves the employee filling out a survey to provide feedback.

- **Access Status: Setup, Revoked**: The attribute 'Access Status: Setup, Revoked' indicates the current status of the remote access configuration.
- **Performance Rating: Excellent, Good, Average, Poor**: The attribute 'Performance Rating: Excellent, Good, Average, Poor' specifies the possible ratings for employee performance evaluation.
- **Notification Status: Sent, Pending**: The attribute 'Notification Status: Sent, Pending' indicates whether the notification to the employee has been sent or is still pending.
- **Survey Score: float between 0.0 and 10.0**: The attribute 'Survey Score: float between 0.0 and 10.0' represents the score given by the employee in the survey.

## Constraints
- **Init[Submit Request] | |**: The 'Submit Request' must be the first activity to occur in the process.
- **Absence[Reject Request] | |**: The 'Reject Request' must not occur in the process.
- **Chain Precedence[Review Request, Submit Request] | | |**: The 'Submit Request' activity can occur only if it is immediately preceded by 'Review Request' activity, with no other activities occurring in between.
- **Response[Submit Request, Review Request] | | |0,24,h**: If a 'Submit Request' activity occurs, then a 'Review Request' activity must eventually occur after the 'Submit Request' event at some point in the same process instance, within 0 to 24 hours. There is no requirement on how soon or what events may occur in between. Multiple 'Submit Request' can be pending at the same time, and a single 'Review Request' can fulfill the obligation for all preceding 'Submit Request'. If 'Submit Request' does not occur, the constraint imposes no obligation on the occurrence of 'Review Request'.
- **Choice[Approve Request, Reject Request] | | |**: At least one of the activities 'Approve Request' or 'Reject Request' must occur in the process instance. This means that the process is compliant if 'Approve Request' event occurs, 'Reject Request' event occurs, or both occur. There is no restriction on the order or the number of times they occur. However, if neither 'Approve Request' nor 'Reject Request' occurs, the constraint is violated.
- **Precedence[Setup Remote Access, Approve Request] | | |**: The 'Approve Request' activity is permitted to occur only if a 'Setup Remote Access' activity has occurred before it within the same process instance.
- **Chain Succession[Approve Request, Notify Employee] | | |**: Whenever a 'Approve Request' activity occurs, it must be immediately followed by a 'Notify Employee' activity, with no other events in between. Conversely, whenever a 'Notify Employee' event occurs, it must be immediately preceded by a 'Approve Request' event, with no other events in between.
- **Alternate Response[Monitor Performance, Update Payroll] | | |0,48,h**: If a 'Monitor Performance' activity occurs, then a 'Update Payroll' activity must occur after that 'Monitor Performance' event and before any subsequent 'Monitor Performance' occurs, no other occurrence of 'Monitor Performance' is allowed between a 'Monitor Performance' and 'Update Payroll'. This must happen within 0 to 48 hours.
- **Not Co-Existence[Revoke Access, Setup Remote Access] | | |**: The 'Revoke Access' activity and the 'Setup Remote Access' activity cannot both occur within the same process instance. This means that if 'Revoke Access' event occurs one or more times, 'Setup Remote Access' must not occur at all in that process instance, and vice-versa. It is acceptable for neither event to occur. The constraint enforces a mutual exclusion between 'Revoke Access' and 'Setup Remote Access', allowing for different process variants based on which event (if any) occurs.
- **Chain Response[Complete Survey, Notify Employee] | | |0,72,h**: Whenever a 'Complete Survey' activity occurs, it must be immediately followed by a 'Notify Employee' activity in the next event position, with no other events in between, within 0 to 72 hours. The 'Notify Employee' activity is allowed to happen isolated.
